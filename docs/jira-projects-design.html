Jira tickets and project pages for Ally

Replace the Todo tab with your Jira tickets, hand a ticket to Claude for planning in one click, and add a Projects tab that opens animated project pages on claude.ai. This page shows the design and how to build it so it stays fast and uses as few Claude tokens as possible.

Status: proposal, revision 5 (Tasks tab joining todos and Jira, refresh on demand, phases). Nothing built yet. Ticket, people and project data on this page are examples.

Recommendation

  • A Tasks tab joins your todos and Jira tickets. It shows your tickets, the ones you follow, the labels you add as filters, and your todos under Personal. Following a ticket uses Jira's own Watch, so it stays the same in Jira and in the widget. A ticket assigned to someone else shows their initials.
  • "Plan with Claude" starts at once, with no confirmation. The widget works out your ticket skill and the repository by itself, opens the terminal, and shows a short notice with a Change link in case it guessed wrong. Your skill runs as /your-skill CM-42; with no skill, the built-in planning prompt runs instead. Either way the widget passes the ticket, so Claude does not spend turns fetching it.
  • A project does not need an epic. Its progress comes from a linked epic or label when it has one, read live from Jira; otherwise from its own checklist, where the current todos move. Right-click a project to create an epic for it, and follow other people's epics or labels as projects.
  • One artifact for all projects, with one view per project, reading Jira live through your claude.ai Atlassian connector at no Claude token cost. Only checklist projects have to be sent to the page, when you press Update board: Ally copies them, you paste them into the board, no Claude involved. Nothing refreshes in the background.
  • The app becomes Ally, with the command ally, described as working with Claude Code. What the rename touches.
  • Start with a two-day spike to confirm what this design depends on but that I could not test from here (listed under Unknowns).
1 · In the widget

Tasks tab, ticket menu and Projects tab

The tabs become Usage · Sessions · Tasks · Projects. Tasks joins your todos and your Jira tickets in one list with one look: a todo is a row without a Jira key. The Today/Week/All chips become statuses, each with its count; a todo is To Do, In Progress or Done and falls under the matching chip. A second row picks what you see: Mine, Following, any labels you add, and Personal for your todos. The add box still creates a todo. Right-clicking a row opens its menu; a todo's menu adds Send to Jira, which turns it into a ticket, and Add to project.

1b · Plan with Claude

How the widget decides, without asking

Each choice takes the first rule that gives an answer. Everything is read from files on your computer, so deciding costs no tokens and takes a fraction of a second.

Which skill

  • The one you last chose with Change for this Jira project.
  • Otherwise a skill whose name or description says Jira or ticket: one in the repository first, then your own, then plugins. A match in the name beats a match in the description.
  • Otherwise the built-in planning prompt.

Which repository

  • The one you last chose with Change for this Jira project.
  • Otherwise a folder where you have run Claude Code that has a git branch named after the project's tickets, such as CM-37-retry.
  • Otherwise a folder named like the Jira project.
  • Otherwise your home folder, and the prompt tells Claude the repository is unknown.

Which mode

  • Built-in prompt: plan mode, so Claude reads and plans but cannot edit.
  • Your skill: Claude Code's normal mode, so a skill that writes a plan file still works. Claude Code asks before any edit.
2 · On claude.ai

One artifact: the projects board and a page per project

A single artifact holds the board of all projects and a view per project. The widget links to a view with a plain #name at the end of the artifact's address (for example #cm), the only kind of deep link artifacts pass to the page.

written by Claude on click · kept until the tickets change

Done, remaining, blocking and due dates are worked out by the page's own code from the Jira data. Only the "Next step" sentence comes from Claude.

Epic and label projects: live

The page reads their tickets from Jira itself. They are always current, and nobody has to send anything.

Checklist projects: sent on change

Their items are todos on your computer, which the page cannot read. Listing them in the widget costs nothing. They reach the board only when you press Update board in the Projects tab. Ally copies them to your clipboard and opens the board at #name~paste; you click the paste box and press ⌘V, and the page keeps the copy in its own private storage (the artifact's db) until the next update. No Claude, no tokens, nothing written to Atlassian. The address itself cannot carry them: claude.ai drops a #part longer than about 100 to 250 characters.

Followed projects: Jira only

You can follow someone else's epic or label, which Jira knows about. A checklist project exists only on its owner's computer, so others cannot follow it until it gets an epic.

Why the widget reads Jira itself

Asking Claude to fetch tickets through the Atlassian connector costs tokens on every refresh, because each answer comes back as long JSON that Claude reads. A direct REST call costs nothing and is faster. Atlassian's new points-based rate limits apply to apps, while personal API-token scripts keep only the short burst limits, so searching on open and on refresh is far below any cap.

Why one artifact and not one per project

Every artifact has to be written and kept up to date by Claude. One page that reads Jira live and routes on #name is written once; a new project appears on it with no Claude involved.

Signing in to Jira from the widget

The widget cannot use your claude.ai connector, so it needs its own access. An Atlassian API token (site, email, token) is the simple choice for a personal tool. It is stored with the system keychain through Electron. OAuth would need a registered app and a server, which a local widget does not have.

5 · Unknowns

What the spike has to prove first

The connector inside the artifact

Artifacts may call your claude.ai connectors, but I have not seen the exact tool names and arguments the page must use for Jira, nor whether connector calls from a page have their own limits. A known issue reports broken paging in the Atlassian connector's search. If this fails, the page falls back to data the widget publishes, which costs a little Claude per update.

Deep links into one project

Artifacts pass a plain #name to the page when opened on their own page. Opened beside a chat or in an app, the hash may not reach it. The spike checks that a widget click lands on the right project.

Opening a terminal everywhere

macOS (Terminal and iTerm2) and Windows (Windows Terminal, else a console window) are well understood. Linux depends on the terminal installed: gnome-terminal, konsole, or the system default.

What "blocked" means

The design counts a ticket as blocked when it has an open "is blocked by" link or the Flagged field set. Teams use Jira differently, so this rule should be a setting.

Guessing the skill and repository

None of the 81 skills on this computer is about Jira today; six mention "issues" in other senses, such as code issues. That is why the rules match only "Jira" or "ticket", and why the notice after each click offers Change. Each skill also has to accept a ticket key after its name, the likely case.

Sending checklists to the page

This needs Claude Code signed in, with the artifacts connector. The cost of one short run is mostly Claude Code's own start-up context: the spike measures it before checklist projects are built.

6 · Plan

Phases

The same phases are written in the repository, in ROADMAP.md. Each one ships on its own, with tests and CI green on Linux, macOS and Windows.

Phase 0 · Rename to Ally

Package, ally command, window title, data folder moved from ~/.claude-meter, hooks, launchers and the GitHub repository. Done when an existing install keeps its settings and todos after upgrading.

Phase 1 · Spike, about two days

The connector read from an artifact, the #name link, opening a terminal on each system, and the tokens of one Update board run (it could not publish; replaced by the clipboard hand-off). Nothing here ships.

Phase 2 · Tasks tab, read only

Jira settings; one search for Mine, Following and labels; status and scope chips; todos in the same list under Personal; refresh on open and with a button.

Phase 3 · Actions

Ticket menu (move, plan, follow, follow label, open, copy key), todo menu (send to Jira, add to project, plan), and one-click Plan with Claude.

Phase 4 · Projects tab

Epic, label and checklist projects; a checklist project's items are todos; the project menu; following someone else's epic or label.

Phase 5 · Projects board on claude.ai

Board and project views, animated, live from Jira with a refresh button; checklist projects through Update board (clipboard and ⌘V, kept in the artifact's db); the next-step sentence on click. Private to you.

7 · Name

Decided: Ally

The app is called Ally, its command is ally, and it is published as @sira-ndiaye/ally. Its description says, in plain text, that it works with Claude Code. That keeps Anthropic's marks out of the name, as its trademark guidelines require for anything not "specifically permitted", while still telling people what it is for.

What the rename touches

The package name and the ally command; the window title and tray label; the data folder, moved from ~/.claude-meter to ~/.ally on first start; the hooks in Claude Code's settings; the launchers and start-at-login entries, removed under the old name and added under the new one; the GitHub repository name.

Wording to use

"Ally: your usage, sessions, Jira tickets and projects, for Claude Code." No Claude or Anthropic logo, and no wording that suggests Anthropic made or endorses it.

8 · Decisions

Decided

  1. The app is Ally, command ally.
  2. Todos stay, joined with Jira tickets in the Tasks tab; a checklist project's items are todos.
  3. Nothing refreshes in the background: lists refresh on open and with a refresh button. Checklist projects reach the board only through Update board.
  4. The board is for you only, so it needs no sharing setup.
